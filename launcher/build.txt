Build (from launcher/, with JDK 25 on PATH or in JAVA_HOME; the wrapper downloads Maven itself):
mvnw.cmd verify                  (compile the module, run the unit tests; no download, no image)
mvnw.cmd verify -Pimage          (also the app image in target/dist/VertexForge Launcher/)
mvnw.cmd compile javafx:run      (run the launcher from target/classes, JavaFX from the Maven jars)

The app image (VK-1692) is a jlink runtime plus the launcher module:
- runtime/ is linked from the JDK's jmods (or, on a JDK without them, its run-time image), the Gluon JavaFX jmods and
  the Gson jar. On first use the image profile downloads the JavaFX jmods zip, checks its SHA-256 (pom.xml) and keeps
  it in ~/.m2/repository/.cache/vertexforge; a zip put there by hand is used when its checksum matches.
- app/mods/VertexForgeLauncher.jar is the shipped jar, built by the jar tool from target/classes with the repo's
  VERSION as its module version (target/VertexForgeLauncher.jar is only Maven's own artifact).
- The exe's version resource and jpackage.app-version are the repo-root VERSION: MAJOR.MINOR.PATCH, each part at most
  65535 (the exe's version resource cannot hold more).
- CI fails an image above 70 MiB, with build output in it, or with other runtime modules than module-info.java needs.
  A new `requires` therefore also goes into the pom's jlink --add-modules and launcher.yml's MODULES list
  (LauncherModuleTest pins module-info.java).

Note: the launcher carries no project templates. New projects are made from the selected engine's own templates and
script library, the folders its engine.json names (VK-1689). The unit tests read the repo's assets/ and VERSION
(RealEngineContentTest, LauncherModuleTest), so run them from the full repo checkout.

Self-test (CI runs this on the packaged image; exit code 0 = pass, 1 = fail):
"target/dist/VertexForge Launcher/VertexForge Launcher.exe" --self-test --self-test-packaged --self-test-report=self-test.txt
The packaged exe has no console, so read the report file; without --self-test-report it shows nothing.
--self-test-packaged adds the checks only the image passes: its own exe, and the module it runs as (name, version,
exports and opens, native access, JavaFX and Gson linked into the runtime, JavaFX's natives in runtime/bin/javafx).

jpackage 25 leaves the generated exe read-only; the pom's clean plugin (3.5.0, force) still deletes it.
